Тексты правил MISRA C:2012 для вывода анализатора (ТД-5).

ЭТО НЕ ОФИЦИАЛЬНЫЙ ТЕКСТ. Формулировки написаны заново, своими словами, и
служат единственной цели — чтобы вывод `cppcheck --addon=misra` читался, а не
состоял из одних номеров. Официальная публикация MISRA C:2012 распространяется
по платной лицензии, и её текст в репозиторий курса помещать нельзя.

Классификация («какое правило нарушено») берётся из аддона misra, входящего в
cppcheck, — то есть это тоже переложение, а не первоисточник. Подробнее
о порядке проверки и о том, чем такая проверка является и чем не является, —
в docs/misra-report.md.

Формат файла задан аддоном: строки «Rule N.M <категория>», за каждой — строка
с текстом, начинающаяся с латинской буквы (ограничение разбора в misra.py).
Поэтому каждая формулировка начинается с «MISRA N.M».

Appendix A Summary of guidelines

Rule 2.2 Required
MISRA 2.2 — мёртвого кода быть не должно: операция, результат которой нигде не используется, только запутывает читателя

Rule 2.3 Advisory
MISRA 2.3 — неиспользуемых определений типов быть не должно

Rule 2.4 Advisory
MISRA 2.4 — неиспользуемых тегов структур, объединений и перечислений быть не должно

Rule 2.5 Advisory
MISRA 2.5 — неиспользуемых макросов быть не должно

Rule 3.1 Required
MISRA 3.1 — последовательности символов комментария не должны встречаться внутри комментария

Rule 5.4 Required
MISRA 5.4 — имена макросов должны различаться в пределах значащей длины

Rule 5.7 Required
MISRA 5.7 — имя тега структуры, объединения или перечисления должно быть уникальным

Rule 5.8 Required
MISRA 5.8 — имена объектов и функций с внешней компоновкой должны быть уникальны во всей программе

Rule 5.9 Advisory
MISRA 5.9 — имена объектов и функций с внутренней компоновкой тоже стоит делать уникальными

Rule 7.3 Required
MISRA 7.3 — суффикс целочисленного литерала пишется заглавной L: строчная путается с единицей

Rule 7.4 Required
MISRA 7.4 — строковый литерал нельзя присваивать указателю на изменяемые символы

Rule 8.2 Required
MISRA 8.2 — функция объявляется прототипом с именованными параметрами

Rule 8.4 Required
MISRA 8.4 — у объекта или функции с внешней компоновкой должно быть видимое совместимое объявление

Rule 8.5 Required
MISRA 8.5 — внешний объект или функция объявляется один раз, в одном заголовке

Rule 8.6 Required
MISRA 8.6 — у объекта или функции с внешней компоновкой должно быть ровно одно определение

Rule 8.7 Advisory
MISRA 8.7 — объект или функцию, нужную только в одной единице трансляции, следует объявлять static

Rule 8.9 Advisory
MISRA 8.9 — объект, используемый только в одной функции, стоит объявлять внутри неё

Rule 8.11 Advisory
MISRA 8.11 — при объявлении массива с внешней компоновкой размер указывается явно

Rule 9.2 Required
MISRA 9.2 — инициализация структур и массивов должна быть заключена в фигурные скобки по уровням

Rule 9.3 Required
MISRA 9.3 — массив инициализируется целиком, а не частично

Rule 10.1 Required
MISRA 10.1 — операнд должен принадлежать типу, допустимому для этой операции

Rule 10.2 Required
MISRA 10.2 — арифметика над символьными типами допустима лишь в узком наборе случаев

Rule 10.3 Required
MISRA 10.3 — значение нельзя присваивать объекту другой или более узкой категории типов

Rule 10.4 Required
MISRA 10.4 — операнды бинарной операции должны принадлежать одной категории типов

Rule 10.5 Advisory
MISRA 10.5 — приведение значения к другой категории типов нежелательно

Rule 10.8 Required
MISRA 10.8 — значение составного выражения нельзя приводить к другой или более широкой категории типов

Rule 11.5 Advisory
MISRA 11.5 — преобразование указателя на void в указатель на объект нежелательно

Rule 11.9 Required
MISRA 11.9 — нулевой указатель записывается только макросом NULL

Rule 12.1 Advisory
MISRA 12.1 — порядок вычисления выражения задаётся скобками явно, а не приоритетом операций

Rule 12.2 Required
MISRA 12.2 — величина сдвига не должна превышать разрядность типа

Rule 12.3 Advisory
MISRA 12.3 — оператор запятая применяться не должен

Rule 13.3 Advisory
MISRA 13.3 — выражение с инкрементом или декрементом не должно иметь иных побочных эффектов

Rule 13.4 Advisory
MISRA 13.4 — результат присваивания использовать не следует

Rule 14.2 Required
MISRA 14.2 — цикл for должен быть построен правильно: счётчик, условие и шаг относятся к одному объекту

Rule 14.4 Required
MISRA 14.4 — условие ветвления должно иметь булев тип, а не число или указатель

Rule 15.4 Advisory
MISRA 15.4 — из цикла должен быть не более чем один выход через break или goto

Rule 15.5 Advisory
MISRA 15.5 — у функции должна быть единственная точка выхода, в конце тела

Rule 15.6 Required
MISRA 15.6 — тело ветвления или цикла заключается в фигурные скобки, даже если оно из одной строки

Rule 15.7 Required
MISRA 15.7 — цепочка if / else if завершается ветвью else

Rule 16.4 Required
MISRA 16.4 — в каждом переключателе должна быть ветвь default

Rule 17.2 Required
MISRA 17.2 — функция не должна вызывать себя ни прямо, ни через другие функции

Rule 17.3 Mandatory
MISRA 17.3 — функцию нельзя вызывать без объявления

Rule 17.7 Required
MISRA 17.7 — возвращаемое значение функции должно быть использовано либо явно отброшено

Rule 17.8 Advisory
MISRA 17.8 — параметр функции изменять не следует

Rule 18.4 Advisory
MISRA 18.4 — арифметику сложения и вычитания к указателям применять не следует

Rule 20.1 Advisory
MISRA 20.1 — директивы включения ставятся до любого кода

Rule 20.10 Advisory
MISRA 20.10 — операторы препроцессора для склейки и превращения в строку применять не следует

Rule 21.1 Required
MISRA 21.1 — зарезервированные идентификаторы переопределять нельзя

Rule 21.3 Required
MISRA 21.3 — выделение и освобождение памяти из стандартной библиотеки запрещено

Rule 21.6 Required
MISRA 21.6 — стандартные средства ввода и вывода применять нельзя

Rule 21.7 Required
MISRA 21.7 — функции преобразования строки в число без диагностики ошибок применять нельзя

Rule 21.9 Required
MISRA 21.9 — стандартные поиск и сортировку применять нельзя

Rule 21.10 Required
MISRA 21.10 — стандартные средства даты и времени применять нельзя

Rule 21.16 Required
MISRA 21.16 — побайтовое сравнение памяти нельзя применять к объектам, тип которых не сводится к байтам

Rule 22.8 Required
MISRA 22.8 — переменную ошибки следует обнулить перед вызовом функции, которая её устанавливает

Rule 22.9 Required
MISRA 22.9 — переменную ошибки следует проверить после такого вызова
