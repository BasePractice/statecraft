## 0. Как пользоваться

1. Прочитать § 3 «Текущее состояние» — понять, что уже сделано.
2. Выбрать очередь работ из § 8 или конкретную лекцию из § 6.
3. Перед правкой лекции прочитать соответствующий раздел `REPORT.md` § 6
   (структура лекции) и § 5 (примеры) — здесь они пересказаны, но в
   первоисточнике подробнее.
4. После правки — прогнать проверку из § 10.
5. Отметить сделанное прямо в этом файле (снять пункт, дописать дату).

**Правило:** ненаписанное помечается блоком `#todo[...]`, а не молчаливым
пропуском. Блок виден в PDF красной врезкой; `show-todo: false` в
`lectures/course.typ` убирает все такие врезки перед раздачей студентам.

## 1. Быстрый старт для новой сессии

Весь курс одной сборкой — PDF лекций и примеры практикума:

```bash
cd /Volumes/HOME/GitHub/statecraft
cmake -S . -B build           # typst + компилятор C
cmake --build build -j        # PDF в build/lectures/, бинарники примеров
ctest --test-dir build        # тесты примеров
cmake --build build --target style-check
```

Работа только над лекциями — быстрее через скрипты:

```bash
cd lectures
./scripts/check.sh --fix      # окружение: typst, шрифты, пути, пробная сборка
./scripts/build.sh            # все 10 лекций в out/
./scripts/build.sh -w 04-dfa-nfa   # watch одной лекции при правке
grep -rn '#todo\[' src/       # что не написано
```

Требуется: `typst` ≥ 0.15, `cmake` ≥ 3.16, компилятор C; `pandoc` — только для
`tex2typ.sh`, `clang-format` — только для полной проверки оформления.
Пакеты `@preview` (fletcher, CeTZ) прогреваются `./scripts/vendor-packages.sh`.

### 3.1. Инфраструктура сборки — сделано 16.08.2026

Одна сборка на весь курс: корневой `CMakeLists.txt` подключает `practices`
(примеры) и `lectures` (PDF через typst). Реестр лекций CMake читает из
`course.typ` тем же способом, что и `scripts/lib.sh`, — источник правды не
раздваивается. Цели: `lectures`, `lecture-<id>`, `style-check`, `style-fix`;
тесты примеров зарегистрированы в `ctest`.

Что было и что стало:

| Было | Стало |
|---|---|
| `cmake_minimum_required(VERSION 3.2.1)` — CMake 4.x отказывается конфигурировать | 3.16 в корне и во всех подпроектах |
| строгие флаги записаны в несуществующую переменную `CMAKE_CFLAGS` — **не применялись вовсе** | `statecraft_strict_c()`: `-std=c90 -pedantic -Wall -Wextra -Wshadow -Wstrict-prototypes …`, при `STATECRAFT_STRICT=ON` (по умолчанию) — `-Werror` |
| `07-fsm-insert-element` не собирался (нет `size_t`), Catch2 v2.3.0 не компилировался на arm64 | собирается всё, 5/5 тестов проходят на macOS arm64 |
| `<stdbool.h>`/`<stdint.h>` в 15 файлах — заголовки C99 | `common/base_types.h`: те же имена средствами C90, штатные заголовки подключаются, если компилятор C99/C++ |
| 114 предупреждений компилятора | 0 |
| требования к оформлению кода — только текстом в `_1.CodeStyle` (каталог удалён 16.08.2026) | `.clang-format` + `scripts/check-style.sh` (табуляция, длина строки, `//`, BOM, CRLF, пробелы в конце) |
| CI нет | `.github/workflows/ci.yml`: оформление, практикум на ubuntu и macOS, лекции с выкладкой PDF |

Исправленные при этом дефекты кода: неинициализированное состояние автомата в

## 9. Грабли typst 0.15 и приёмы

Записаны по итогам работы; экономят время при следующих правках.

- Угловые скобки — только `chevron.l` / `chevron.r`. `angle.l` даёт
  «unknown symbol modifier».
- Единственный встроенный ГОСТ-стиль библиографии — `gost-r-705-2008-numeric`.
- Fira Code — variable-шрифт с начертанием по умолчанию Light (300); вес
  задан явно в `template/theme.typ`.
- Счётчик `figure` шагает по первому уровню и «схлопывает» двумерное
  значение, поэтому утверждения нумеруются сквозным номером по лекции.
- `read()` и `image()` внутри файлов шаблона разрешают относительные пути от
  самого шаблона: в `code-file` и `img` нужен абсолютный путь от корня
  (`/src/<id>/code/foo.c`). Внутри файла лекции обычный
  `image("images/foo.png")` работает как относительный.
- В подписи печатается полное слово («Рисунок 3 — …»), в ссылке —
  сокращение («на рис. 3»): иначе получается «приведена на Рисунок 3».
  Сделано show-правилом в `template/figures.typ`.
- В CeTZ общий `set-style(mark: ...)` навешивает наконечники на **все** пути
  холста, включая контуры фигур и транзитные линии. Стрелку задавать явно
  только на тех линиях, которые входят в элемент или уходят за пределы схемы.
- В fletcher `loop-angle` принимается только для петель; для обычных дуг
  значение `auto` роняет компиляцию. Петля без явного `bend` рисуется внутри
  узла и накрывает подпись — задавать `bend: 130deg`.
- `typst eval` требует, чтобы пробный файл лежал внутри `--root`.

### После конвертации из LaTeX проверять отдельно

Эти дефекты уже встречались и могут повториться при переносе новых файлов
через `scripts/tex2typ.sh`:

- вызовы `image(...)` теряют решётку и печатаются как текст;
- `&` из LaTeX превращается в `and` внутри `cases(...)`, создавая пустые
  строки в фигурных скобках;
- метки `<fig:...>` привязываются к следующему заголовку вместо рисунка;
- уровни заголовков сдвигаются, если исходную лекцию разрезали на части;
- `\,` из LaTeX становится тонким пробелом typst вместо запятой.
