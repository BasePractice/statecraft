# 08-bulk-loading — загрузка сыпучих материалов

Практика к лекции 8. Пример промышленного размера: одиннадцать состояний,
восемь входов, семь выходов, выдержки времени и рецепт.

Установка: по рельсу ездит контейнер, над рельсом стоят три резервуара с
сыпучим материалом. Контейнер подъезжает под нужный резервуар, открывает
заслонку, набирает материал в течение выдержки, закрывает заслонку, едет к
следующему; набрав всё по циклу, возвращается в исходное положение, где его
разгружают.

Автомат перенесён из репозитория
[c_fsm](https://github.com/BasePractice/c_fsm) (модуль `fsm_bulk`).

## Запуск

```bash
08-bulk-loading            # рецепт 5151, печать циклограммы по тактам
08-bulk-loading 1001       # свой рецепт
08-bulk-loading 5151 --quiet
```

Рецепт — десятичное число: младшая цифра задаёт первый малый цикл, каждая
цифра — маска резервуаров (бит 0 — первый, бит 1 — второй, бит 2 — третий).
Например `5` = `101` — первый и третий.

## Что здесь существенно

**Автомат ничего не знает о вводе-выводе.** Вход — регистр датчиков, выход —
регистр команд, такт — функция без побочных действий, кроме смены состояния.
В оригинале автомат сам открывал файл, сам читал из него входы и сам печатал;
такой автомат нельзя ни проверить тестом, ни подключить к другой установке.

**Установка — модель, а не запись.** Вместо файла с заранее снятыми входами
здесь модель, которая отвечает на команды: поехал — координата меняется,
открыл — заслонка идёт несколько тактов, запустил выдержку — счётчик тикает.
Разница практическая: запись приходится переснимать после каждой правки
автомата, а модель проверяет именно управление.

**Авария обрабатывается до разбора состояний.** Снятие питания и сигнал
аварии проверяются один раз в начале такта, а не в каждой ветви: забытая
ветвь означала бы, что установка продолжает работу после аварии. Из состояния
отказа автомат сам не выходит, даже если установка «починилась».

**Возврат в исходное положение — не украшение.** У автомата нет координаты,
только датчик «под резервуаром». Резервуары стоят слева друг за другом, и
следующий цикл всегда начинается с самого правого из нужных, поэтому без
возврата автомат погнал бы контейнер влево из позиции, которая уже левее
цели, и упёрся бы в упор. Этот дефект и был обнаружен прогоном на модели —
в оригинале он не проявлялся, потому что входы читались из файла.

## Дефекты оригинала, исправленные при переносе

| Что было | Чем это грозит |
|---|---|
| по истечении выдержки подавалась команда «открыть заслонку», а сигнал «закрыть» был объявлен и не использован ни разу | заслонка закрывалась случайно, на переходе следующего состояния |
| счётчик малых циклов увеличивался без ограничения, а бит рецепта читался по этому счётчику | чтение за границей массива при длинном прогоне |
| сигналы большого круга (`EndBigSequence`, `NextBigCircle`, `ResetCounter`) объявлены и не используются | большой круг не реализован, хотя в модели заявлен |
| результат `fopen` не проверялся | при отсутствии файла автомат молча зависал |
| `print_state` писала в статический буфер | не работает при двух автоматах в одном процессе |

Отдельная ловушка, найденная уже на этом коде: **поля общих структур не стоит
объявлять `bool`**. Тесты собираются компилятором C++, где `bool` занимает
один байт, а код курса — как ISO C90, где `bool` из `base_types.h` — это
`int`. Структура, у которой `bool` стоит не последним полем, получает в двух
трансляциях разную раскладку, и тест читает мусор (в этой практике — падал с
SIGSEGV). Пока `base_types.h` устроен так, безопаснее целые.

## Тесты

| Утверждение | Как проверяется |
|---|---|
| рецепт разбирается по цифрам | 5151 → циклы 1, 5, 1, 5 |
| негодный рецепт отвергается | цифра 8 при трёх резервуарах, пять цифр при четырёх циклах |
| установка выходит в исходное положение сама | модель стартует у последнего резервуара |
| рецепт исполняется целиком | 5151 → первый резервуар 4 раза, третий 2, второй ни разу |
| пустой цикл пропускается | 1001 → первый резервуар дважды |
| заслонка закрывается по команде | команда «закрыть» действительно подаётся |
| все состояния достижимы | кроме аварии — её на исправной установке быть не должно |
| снятие питания останавливает установку | автомат в отказе, все команды сняты |
| авария необратима | автомат не возвращается в работу после «починки» |
| без команды оператора цикл не начинается | материал не набран ни разу |
