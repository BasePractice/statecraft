# statecraft — контекст репозитория

Учебный курс «Автоматное программирование систем управления» (АПСУ): лекции,
практикум на C90, модели SimInTech, примеры Promela/SPIN. Origin — <https://github.com/BasePractice/statecraft>.
Исторически репозиторий назывался `automata_programming` (следы остались в
абсолютных путях внутри сгенерированного кода).

## lectures/ — как устроено

Полное описание в `lectures/README.md`. Коротко:

- `course.typ` — **единственное** место правки автора, института, кафедры,
  даты, версии и реестра лекций. Этот же файл читают bash-скрипты
  через `typst eval`, поэтому список лекций нигде не дублируется.
- `template/` — шаблон: `theme`, `i18n`, `blocks`, `code`, `figures`,
  `frontmatter`, `appendix`, `lecture`. Базовый шаблон не зависит ни от
  одного `@preview`-пакета и собирается офлайн.
- `shared/` — единая нотация, глоссарий, банк контрольных вопросов и задачник.
- `src/<id>/main.typ` + `main.body.typ` — лекция. Разделение нужно, чтобы
  `scripts/tex2typ.sh` можно было перезапускать, не теряя ручной обвязки.
- `scripts/` — `check.sh`, `build.sh`, `clean.sh`, `sync-code.sh`,
  `fetch-fonts.sh`, `vendor-packages.sh`, `tex2typ.sh`.
- Сборка лекций описана **только** в `lectures/Makefile` и `scripts/`:
  `lectures/CMakeLists.txt` вызывает `make pretty OUT=<build>/lectures`, а не
  повторяет логику компиляции. Поэтому лекции собираются и без CMake
  (`cd lectures && make`), и порядок сборки в обоих случаях один.
- `scripts/sync-code.sh` держит листинги лекций (`src/<id>/code/`) равными
  файлам практикума; соответствие — в `scripts/code-map.txt`, проверка
  `make sync-check` стоит в CI. Копии нужны потому, что typst читает файлы
  только из своего `--root`.
- `template/diagrams.typ` — единственный файл с `@preview`-зависимостями
  (fletcher для диаграмм состояний, CeTZ для структурных схем). Подключается
  только теми лекциями, где есть векторные рисунки; кэш прогревается
  `scripts/vendor-packages.sh`. Карты Карно (`karnaugh-map`) внешних пакетов
  не требуют и живут в `template/figures.typ`.

```bash
cmake -S . -B build && cmake --build build -j   # весь курс: PDF + примеры
ctest --test-dir build                          # тесты примеров
./scripts/check-style.sh                        # оформление кода

cd lectures && make fix && make                  # только лекции (make = make pretty)
cd lectures && make sync-check                  # листинги лекций против practices/
```

### Ловушки typst 0.15, на которые уже наступили

- Угловые скобки — только `chevron.l` / `chevron.r`. `angle.l` даёт
  «unknown symbol modifier».
- Единственный встроенный ГОСТ-стиль библиографии — `gost-r-705-2008-numeric`
  (не `gost-r-7-0-5-2008`).
- Fira Code установлена как variable-шрифт с Default weight 300 (Light) —
  вес задан явно в `template/theme.typ`.
- Счётчик `figure` шагает по первому уровню и «схлопывает» двумерное
  значение, поэтому утверждения нумеруются сквозным номером по лекции, а не
  «раздел.номер».
- `read()` и `image()` внутри файлов шаблона разрешают относительные пути от
  самого шаблона: в `code-file` и `img` нужен абсолютный путь от корня
  (`/src/<id>/code/foo.c`).
- Основной текст лекций набирается **Fira Code**: переключатель
  `body-in-mono` в `template/theme.typ` установлен в `true` (требование
  заказчика курса). В этом режиме кегль берётся из `mono-body-size` (9.6 pt
  вместо 11 pt), интерлиньяж — из `mono-body-leading`, а выключка по формату
  отключена: моноширинный шрифт не тянется по ширине знака и даёт дыры между
  словами. При `body-in-mono: false` основной текст — PT Serif с запасным
  Libertinus Serif.
- `fsm-diagram` вписывает диаграмму в полосу набора, если она шире (цепочка
  из шести состояний при `spacing: 3.2cm` уезжала за поля). У состояния есть
  `initial` / `final` (двойной контур) и `entry` (входящая стрелка).

## Проверка 16.08.2026 — что она дала

Полный протокол — в [REPORT.md](REPORT.md). Здесь то, что важно помнить при
следующих правках.

**Release ловит то, чего не видит Debug.** `char_list_find` в машине Тьюринга
не возвращала значения при неудачном поиске: путь заканчивался `assert(0)`,
который в Release исчезает вместе с `NDEBUG`. Debug собирался чисто, Release
падал с `-Wreturn-type`. Поэтому в матрицу CI добавлен Release — без него
такие дефекты не видны. Правило: `assert` не заменяет `return`.

Это повторилось на новом коде в тот же день: в `03-synthesis` импликанты
заполнялись частично, разряды сверх `var_count` оставались мусором со стека.
Debug и санитайзеры молчали (мусор оказывался нулевым), Release уронил два
теста. Правило: структуру с массивами фиксированного размера обнулять
целиком, даже если «используется только начало».

**Зелёные тесты ничего не гарантируют.** В том же файле были выход за границы
ленты, утечки всей таблицы переходов и выделение памяти в восемь раз больше
нужного — при 100 % проходящих тестах. Тесты подавали только корректные
данные. Санитайзеры (`-fsanitize=address,undefined`) тоже молчали по той же
причине.

**Кириллица в формулах.** После конвертации из LaTeX в 29 формулах стояли
русские `А`, `В`, `С`, `М` вместо латинских — визуально неотличимо. При
правке перенесённых лекций стоит прогонять проверку: короткие формулы
`$...$`, содержащие символы из диапазона `[А-Яа-я]`, почти всегда ошибка.

**Запятая внутри `cases()` — разделитель аргументов.** Условие вида
`y(t) = x(t-1), t = 2, 3, …` typst разбирает как четыре строки системы.
Лечится скобками: `y(t) = x(t-1) quad (t = 2, 3, dots)`.

**Модели Promela заявляют ожидаемый исход сами.** Строка
`verify: ok|violation|skip` в шапке модели: часть примеров курса
демонстрирует именно нарушение, и для них отсутствие нарушения — тоже
ошибка. Проверка: `./scripts/check-promela.sh --verify`.

**Копипаста типов между проектами практикума.** `02-fsm-delay` объявлял
`InsertingEngine` — тип из `07-fsm-insert-element` с другим содержимым.
При заведении нового проекта имена типов проверять по всему `practices/`.

### ТД-1. ГОСТ-шрифт в диаграммах — основное сделано 16.08.2026

Все надписи внутри рисунков — подписи состояний, метки дуг, тексты на
структурных схемах и statechart'ах — набираются **чертёжным шрифтом по
ГОСТ 2.304-81** (ISO 3098). Сделано:

- `fonts.diagram` в `template/theme.typ` (сейчас — `osifont`, свободная
  реализация ISO 3098 под LGPL3 + font exception);
- `template/diagrams.typ` навешивает его на содержимое `figure` у
  `fsm-diagram` и `scheme`. Важно: именно на содержимое, а не `set text` на
  выходе функции — иначе метка `<fig:…>` цепляется к styled-контенту и
  ссылки на рисунок ломаются («cannot reference styled»);
- `scripts/fetch-fonts.sh` (`make fonts`) качает архив по конкретному
  коммиту с проверкой sha256; `scripts/check.sh` (`make check`) проверяет
  наличие. Отсутствие шрифта сборку не роняет — надписи набираются основным
  шрифтом лекции.

Осталось:

- формульные метки (`$q_0$`, `$1\/0$`) по-прежнему набираются математическим
  шрифтом курса: решение осознанное (единообразие формул во всём документе),
  но требует согласования с заказчиком;
- растровые диаграммы, ещё не переведённые в вектор (лекции 3, 5, 11),
  ГОСТ-шрифта, разумеется, не получают — см. `PLAN.md` § 5.7.

### ТД-4. Документирование кода практикума

Снабдить код `practices/` комментариями в формате Doxygen. Объём — минимально
необходимый: комментарий обязан объяснять **зачем** существует сущность и
какого контракта от неё ждут, а не пересказывать, **как** она устроена.

Что документировать:

- каждый публичный заголовок — `@file` с назначением модуля и его местом в
  курсе (к какой лекции относится, что демонстрирует);
- каждую функцию публичного API — назначение, смысл параметров, что означает
  возвращаемое значение (особенно `false`/`NULL`), предусловия и владение
  памятью;
- типы и перечисления — что моделирует тип, чем различаются варианты
  перечисления;
- неочевидные решения — почему сделано именно так: ограничение C90, обход
  чужого дефекта, требование строгого режима компиляции.

Чего не делать:

- не повторять кодом по-русски (`/* увеличиваем счётчик */`);
- не документировать статические функции, смысл которых виден из имени;
- не заводить `@brief`/`@param` там, где сигнатура и имя уже всё сказали, —
  пустой тег хуже его отсутствия.

Инфраструктура: `Doxyfile` в корне, цель CMake `docs` (мягкий пропуск, если
`doxygen` не установлен), задание в CI. Комментарии в коде остаются на
русском языке, как и весь курс; `INPUT_ENCODING = UTF-8`.

### ТД-5. Проверка примеров на соответствие MISRA C

Проверка **факультативная**: код курса пишется на ISO C90 и учит автоматному
программированию, а не сертификации, поэтому MISRA здесь — инструмент оценки,
а не обязательное требование. Смысл задачи в том, чтобы показать студенту, как
выглядит промышленный набор правил для встраиваемого кода и какие места

#### Дефекты, найденные при разборе

Переносить код как есть нельзя: в обоих разобранных модулях есть ошибки.

**`game_life/game_life.c`, функция `around_the_cell` — тор не работает.**
Индексы соседей объявлены как `size_t`, а вычисляются из `int`, который для
левого и верхнего края равен −1:

```c
size_t iy, ix;
iy = ity;                 /* int -1 -> size_t SIZE_MAX */
if (iy < 0) { ... }       /* всегда ложь: тип беззнаковый */
else if (iy >= w->height) iy = 0;
```

Проверка `iy < 0` для беззнакового типа тождественно ложна, поэтому вместо
`height - 1` подставляется 0. Проверено экспериментом: у клетки (0,0) на поле
8×8 «соседями» оказываются `(0,0)` **четыре раза**, `(0,1)` и `(1,0)` — по
два раза. То есть клетка считает соседом саму себя, а противоположный край
поля не учитывается вовсе. Все клетки на левой и верхней границе живут по
неверным правилам. Компилятор предупреждает об этом (`-Wsign-compare`), но
предупреждения в проекте не включены как ошибки.

Там же: `w->output_cells` не инициализируется в `init_world`, а читается в
`poll_world` — чтение неинициализированной памяти; `destroy_world` не
закрывает `w->output`, открытый через `fopen`, — утечка дескриптора;
`around_the_cell` возвращает указатель на `static` массив (сама переменная
названа `not_thread_safe`); `assert(x >= 0)` при `size_t x` бессмысленно.

**`clever_ant/clever_ant.c` — нет ограничения на число шагов.** Цикл
`while (apples > 0)` не завершится, если автомат не съедает всё; счётчик
`steps` типа `uint16_t` при этом молча переполнится. В канонической
постановке лимит — 600 тактов, и он же служит критерием сравнения стратегий.
Кроме того: число яблок задано дважды (`APPLES` в `ant.c` и локальная
переменная `apples = 89`) — при правке карты они разойдутся; всё состояние
автомата в глобальных переменных, поэтому два прогона подряд в одном
процессе невозможны, а тестировать нечем; `assert(false)` в `has_food()`
исчезает в Release вместе с `NDEBUG`, и функция молча возвращает `false` —
ровно тот случай, о котором в разделе «Проверка 16.08.2026» сказано «assert
не заменяет return».
