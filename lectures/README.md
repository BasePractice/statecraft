# Лекции курса АПСУ

Двенадцать лекций и приложение курса в формате [Typst](https://typst.app)
под единым шаблоном. Автор, институт, кафедра, дата и номера лекций правятся
в одном файле — [`course.typ`](course.typ).

## Быстрый старт

```bash
./scripts/check.sh --fix   # проверить окружение и доустановить недостающее
./scripts/build.sh         # собрать все лекции в out/
```

Или через `make`:

```bash
make fix && make
```

## Требования

| Что | Зачем | Установка |
|---|---|---|
| `typst` ≥ 0.15 | сборка | `brew install typst` |
| `pandoc` | только для `tex2typ.sh` | `brew install pandoc` |
| Fira Code, PT Serif, PT Sans, osifont | шрифты | `make fonts` |

Основной шрифт лекций — **Fira Code**: им набирается весь текст, а не только
листинги (переключатель `body-in-mono` в `template/theme.typ`). Надписи внутри
рисунков — подписи состояний, метки дуг, тексты на схемах — набираются
чертёжным шрифтом по ГОСТ 2.304-81 (ISO 3098): семейство `fonts.diagram`,
сейчас это свободный `osifont`. Шрифты не
обязательны — при отсутствии Fira Code шаблон падает на PT Mono и далее на
встроенный в typst DejaVu Sans Mono, покрывающий кириллицу, — но для
воспроизводимой сборки (`STRICT_FONTS=1`) их стоит положить в `fonts/`
скриптом `fetch-fonts.sh`. Внешних typst-пакетов базовый шаблон не
использует, поэтому собирается офлайн.

## Команды

Вход один — `make`; CMake вызывает эти же цели, поэтому порядок сборки описан
в одном месте.

```bash
make                     # все лекции под читаемыми именами (= make pretty)
make build               # только <id>.pdf, без читаемых копий
make one L=03-synthesis  # одну лекцию
make book                # только сводный том (все лекции и приложения одним PDF)
make watch L=03-synthesis# пересборка при изменении
make draft               # с водяным знаком «ЧЕРНОВИК»
make sync                # подтянуть листинги из practices/
make sync-check          # проверить, что листинги не разошлись (стоит в CI)
make highlight           # проверить подсветку листингов в собранных PDF
make check               # проверить окружение
make version             # версия курса из course.typ (она же версия релиза)
make pack                # комплект для раздачи: читаемые имена в одном zip
make clean               # очистить out/
make OUT=/tmp/pdf        # положить результат в другой каталог
```

### Сводный том

Кроме отдельных PDF собирается **сводный том** — все лекции и приложения одним
документом (`book.typ`, читаемое имя «00 — <дисциплина> (полный курс).pdf»,
около шестисот страниц). В нём единое оглавление, сквозная нумерация разделов,
рисунков, таблиц и листингов и **один** список литературы в конце: ссылка
`[24]` означает одно и то же в любой части тома.

Лекция становится разделом первого уровня, её собственные разделы уезжают на
уровень ниже (`set heading(offset: 1)`), приложения курса нумеруются буквами
по ГОСТ 7.32 — «А», «Б». Текст берётся из тех же `src/<id>/main.body.typ`, что
и отдельные лекции, поэтому расхождение между томом и выпуском невозможно.

### Подсветка листингов

Языки, которых typst не знает (Takt, Promela, БНФ), описаны в `syntaxes/` и
подключаются в `template/code.typ`. Указывать язык нужно у **каждого**
листинга, в том числе у вставок `#raw("...", block: true)`: без языка код
набирается одним цветом, то есть выглядит как вывод программы.

Проверяется это не по исходникам, а по результату — `make highlight` читает
собранные PDF, находит плашки листингов и считает цвета текста внутри.
Одноцветные печатаются списком: часть из них законна (вывод программ, ленты
машины Тьюринга, поля клеточных автоматов — они помечены `text`), остальное
означает, что язык не указан или неизвестен typst. Скрипту нужен `pymupdf`;
без него проверка мягко пропускается.

Единственное, что в `book.typ` перечислено руками, — пути включаемых тел:
`include` в typst принимает только литеральный путь. Номера, названия и
порядок по-прежнему берутся из `course.typ`, а `make check` проверяет, что все
включаемые файлы на месте.

Комплект (`make pack`) — то же, что выкладывается релизом: PDF под читаемыми
именами внутри каталога «Лекции АПСУ <версия>», упакованные в
`statecraft-lectures-<версия>.zip`; сводный том лежит там же первым файлом. Версия берётся из `course.typ`, и она же
проверяется по тегу при публикации: `./scripts/course.sh --check v1.1.0`.

`make help` печатает то же самое. Цели `make` — тонкие обёртки над
`scripts/*.sh`; при желании скрипты вызываются напрямую
(`./scripts/build.sh --pretty`), но в CMake и CI ходит именно `make`.

## Структура

```
course.typ         метаданные курса, реестр лекций и приложений —
                   единственное место правки
book.typ           сводный том: все лекции и приложения одним PDF
template/          шаблон: тема, подписи, блоки, листинги, титул, приложения,
                   book.typ — оформление сводного тома
syntaxes/          подсветка языков, которых typst не знает: Takt, Promela, БНФ
shared/            общая нотация, глоссарий, контрольные вопросы, задачник
bib/references.bib единая библиография (стиль gost-r-705-2008-numeric)
src/<id>/          лекция или приложение: main.typ, main.body.typ, images/, code/
scripts/           check, build, clean, sync-code, fetch-fonts, vendor-packages,
                   tex2typ, course (версия и реестр), pack (комплект для раздачи)
scripts/code-map.txt соответствие «файл практикума → листинг лекции»
out/               собранные PDF (в .gitignore)
```

## Как добавить лекцию

1. Добавить запись в реестр `lectures` в `course.typ`.
2. Скопировать `src/_template/` в `src/<новый-id>/`.
3. Заменить `id` в первой строке `main.typ`.

Больше нигде номер, название, дату и автора указывать не нужно.

## Как добавить приложение

Приложение — справочный документ, который не читается на занятии и не имеет
номера в расписании (пример: `src/a1-version-control` о Git). Порядок тот же,
но реестр другой:

1. Добавить запись в реестр `appendices` в `course.typ` (id, название, дата).
2. Завести `src/<id>/main.typ` со строкой
   `#show: lecture.with(appendix-id: "<id>", questions: false, tasks: false)`.

Дальше приложение собирается, проверяется и попадает в комплект наравне с
лекциями; на титуле и в колонтитуле вместо «Лекция N» печатается
«Приложение».

## Как добавить лабораторную работу

Лабораторная работа — задание студенту: постановка, варианты, порядок сдачи и
критерии приёмки (пример: `src/lab-1-synthesis` к лекции 3). Реестр третий,
рядом с лекциями и приложениями:

1. Добавить запись в реестр `labs` в `course.typ` (номер, id, номер лекции,
   название, дата).
2. Завести `src/<id>/main.typ` со строкой
   `#show: lecture.with(lab-id: "<id>", questions: false, tasks: false)`.

Работа собирается и пакуется наравне с лекциями, читаемое имя PDF —
«Лабораторная N — Название»; на титуле и в колонтитуле печатается
«Лабораторная работа N». В сводный том работы не входят: том — это то, что
читают, а задание выдаётся отдельно.

Правило для содержания: каждый шаг задания должен иметь машинную проверку —
прогон практики, тест, сверку с порождённым эталоном. Задание, которое
проверяется только мнением преподавателя, проверяет не курс, а терпение.

## Что доступно в лекции

Один импорт `#import "/template/lecture.typ": *` даёт:

- блоки `#definition`, `#theorem`, `#lemma`, `#corollary`, `#example`,
  `#remark`, `#exercise`, `#proof` — со сквозной нумерацией и работающими
  ссылками (`#theorem[…] <thm:kleene>`, далее `@thm:kleene`);
- `#todo[…]` — видимая в PDF метка ненаписанного фрагмента; выключается
  флагом `show-todo` в `course.typ`;
- `#sources[…]` — врезка о происхождении материала и внесённых правках;
- `#code-file("/src/<id>/code/foo.c", lang: "c", from: 1, to: 40)` — листинг
  из файла (путь **абсолютный от корня** `lectures/`);
- `#img(...)`, `#subfigures(...)`, `#listing(...)`, `#karnaugh-map(...)`;
- `#nota.*` — единая нотация курса из `shared/notation.typ`;
- `#show: appendix` — дальше заголовки нумеруются «Приложение А».

## Векторные диаграммы автоматов

`template/diagrams.typ` — единственный файл шаблона с внешней зависимостью
(`@preview/fletcher`). Базовый шаблон его не импортирует, поэтому лекция без
диаграмм собирается офлайн. Лекции, которым диаграммы нужны, подключают его
явно:

```typst
#import "/template/diagrams.typ": cetz, fsm-diagram, scheme
```

Три средства:

- `fsm-diagram(states, arcs)` — диаграмма Мура на fletcher: узлы-состояния,
  помеченные дуги, петли. У состояния можно задать `initial: true` (двойной
  круг — начальное состояние автомата-преобразователя), `final: true`
  (двойной круг — заключительное состояние акцептора) и `entry: true`
  (входящая стрелка: начальное состояние акцептора, у которого двойной контур
  уже занят). Диаграмма шире полосы набора автоматически вписывается в неё;
- `scheme(body)` — холст CeTZ для структурных (автоматных) схем: блоки,
  шины, обратные связи;
- `karnaugh-map(name, cells)` — карта Карно функции четырёх переменных
  (доступна из основного импорта, внешних пакетов не требует).

В схемах стрелка ставится только там, где линия входит в элемент или уходит
за пределы схемы: общий `set-style(mark: ...)` навесил бы наконечники и на
контуры фигур, и на транзитные участки.

Перед первой такой сборкой прогрейте локальный кэш пакетов:

```bash
./scripts/vendor-packages.sh
```

Пример использования — диаграмма Мура разменного аппарата в
`src/03-synthesis/main.body.typ`.

## Перенос лекции из LaTeX

```bash
./scripts/tex2typ.sh "/путь/к/index.tex" 03-synthesis
```

Скрипт копирует картинки и код, прогоняет `pandoc` и чинит то, что pandoc
ломает (кавычки-ёлочки, `image()` без расширения, теоремы с именем,
`\lstinputlisting`, `\appendix`). Перезаписывается только `main.body.typ`,
поэтому конвертер можно перезапускать. Список мест для ручной доводки
пишется в `src/<id>/TODO.md`.

## Замечания по typst 0.15

- Угловые скобки — только `chevron.l` / `chevron.r`; `angle.l` даёт
  «unknown symbol modifier».
- Единственный встроенный ГОСТ-стиль библиографии — `gost-r-705-2008-numeric`.
- Fira Code — variable-шрифт с начертанием по умолчанию Light (300), поэтому
  в шаблоне вес задан явно (`mono-weight`, `body-weight`).
- Кегль основного текста при `body-in-mono` — `mono-body-size` (9.6 pt против
  11 pt у PT Serif): ширина знака Fira Code больше, и при равном кегле строка
  вмещала бы на четверть меньше знаков.
- Выключка по формату включена (`par-setup.justify`). Моноширинный шрифт не
  тянется по ширине знака, поэтому вся растяжка приходится на пробелы;
  сдерживают её переносы с удешевлённой ценой (`hyphenation-cost`) и
  отключённая выключка в таблицах и подписях (`justify-in-tables`,
  `justify-in-captions`) — там строка короткая, и дыры видны сильнее, чем
  неровный край.
- Отступы вокруг заголовков — `heading-gaps` в `template/theme.typ`: пары
  «above/below» на часть тома, раздел, подраздел, пункт и служебный раздел.
  Значения общие для отдельной лекции и сводного тома. Служебные разделы
  («Содержание», списки рисунков и таблиц, «Обозначения и сокращения»,
  «Контрольные вопросы», «Задачи», «Список литературы») отбираются как
  заголовки без номера и центрируются — `service-heading-align`.
- Слабая отбивка (`v(.., weak: true)`) не берёт максимум с блочной, а
  вытесняет её: из-за `v(6pt, weak: true)` в начале строки списка отбивка
  `below` у заголовка списка пропадала. Отсюда явная отбивка после заголовка в
  `front-outlines`. Там же заголовок печатается отдельно от `outline`, а не
  его параметром `title`.
- Заголовок с `above: 0pt`, идущий сразу за `outline`, рисуется поверх
  последней строки списка. У служебных заголовков `above` ненулевой.
- `read()` и `image()` внутри шаблона разрешают относительные пути от файла
  шаблона, а не от лекции: в `code-file` и `img` указывайте абсолютный путь
  от корня.
